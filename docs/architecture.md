# Architecture

## The question

A cheat is an information flow in which a read that may be missing is quietly swallowed or conflated with an ordinary value. The README lists the families: `default`, `unit`, `container`, `sink`, and `drift`. The first four leave a witness of the form `maybe z f (xs !? k)`: `z` where the read is missing, and `f` of the element where it is present. Drift leaves an `escape`: a read whose index came from another collection's walker, left as a possible hole in a mapped result.

The second question is observable mutation: whether the expression changes, in place, an array or object someone outside it holds. Its evidence is a log of `mutate(op, owner)` terms, separate from the value.

## Pipeline

```
source --oxc_parser--> AST --oxc_semantic--> symbols, references, AST nodes
       --lower (partial evaluation)--> core IR for the value and for the effect log,
                                       and whether it evaluated anything opaque
       --egg (equational saturation of both roots)--> classes --> witnesses, live mutations --> verdicts
```

Lowering decides every question of JavaScript's operational semantics: coercion, arity, method dispatch, effects, statement control flow, and which operations are modeled at all. The core IR is a small language with its own meaning, and egg proves equalities in that language only. Some of that meaning mirrors JavaScript where lowering needs it to: `eq` is strict equality, so `NaN` is unequal to itself; `text` is the text `join` writes for an element; and a `read` outside a list's bounds is `undefined`.

## Lowering: src/lower

A partial evaluator over a static value domain (`value.rs`):

- **Known values**: integers (affine forms with no atoms), `NaN`, strings as UTF-16 code units, booleans, `undefined`, a thrown error, lists of known length, and functions (parameters, body, and the bindings they closed over).
- **Symbolic values**: a core term with a static type: integer (an affine form over atoms), boolean, string, list, defined, or possibly undefined. A list's type records the shape of its elements, and every term has the shape the analysis would give it (the builder computes it as it adds the node, with the same rules). A free list's elements are defined by the model's precondition, or have the shape a declaration gives them. Lowering reads shapes where JavaScript's semantics turn on type: `+` adds when neither operand can be text, a value that can only be an object, array, or function is truthy, a string or list has a `len`, a number or boolean has no length, and `JSON.stringify` of a primitive or a list is never `undefined`. A boolean converts to `1` or `0` in arithmetic and to `'true'` or `'false'` as text. A built list's elements are defined when every value put into it is; for `[undefined, ...ys]`, or a map whose callback may return `undefined`, they are not. An element of such a list binds to an `item` variable, not an `elem` one.
- **Splits**: a value that depends on whether one read is present. A read of a symbolic list at an index not proven in range lowers to a split whose absent side is `undefined` and whose present side is the read's element binder. Every split on one read shares one binder.
- **Short lists**: a symbolic list of at most one element, from a slice whose bounds differ by one, `slice(-1)`, or a filter whose predicate is `index === j` (a projection). Each one carries its element slot, the element's value there, whether a filter keeps it, and whether the slot's index came from another collection's walker.

Operations are typed (`ops.rs`):

- Integer arithmetic stays affine, and a form whose constant or any coefficient exceeds 2^53 - 1 is not folded.
- `+` concatenates when an operand is a string or a list, and otherwise adds, with booleans coerced. An `undefined` or `NaN` operand gives `NaN` only next to an operand that `+` would add.
- Ordering against `undefined` is `false`. Two lists or functions lowering built are strictly equal only if they are one object.
- An operation on a value of unknown type becomes an uninterpreted `dyn` term that is never `undefined`. The one exception is `x ?? y` of an unknown `x` with a fallback that may itself be `undefined`, which becomes `dyn?`.

Every operation lifts over splits: it applies on both sides, each in its own world with the split's read narrowed. A split's family is the last operation that wrote its absent side, with two qualifications. An operation that only passes values through (a read, `length`, a spread) keeps the family it was given. An undecided step, `===` against or `??` toward an unknown, leaves the whole chain undecided, since for some value of the unknown the chain only tests presence. Branches (`expr.rs`) lower each arm in every world of the splits in their test. Presence tests, `&&`, `||`, and `??` all narrow this way, and a binding's value, or a literal list's item, settles to the worlds the enclosing branches decided when it is used. A conditional on a symbolic test that is not a split swallows nothing itself; egg labels it a default if the test proves to be the read's own presence test.

Effects are strict. Array elements, a call's callee or receiver and arguments, `const` initializers, and binary operands are evaluated before what follows: lowering runs what follows on the values as they are, then makes every world in which one of them throws throw. Calling a value that is not a function, or reading a property of `undefined`, throws. Lowering also reports whether it evaluated anything opaque: a construct it does not model, a call it could not resolve, a walker over an unknown callback, or a spread of a value of unknown type. Any of these may throw, loop, or mutate, so the expression's value is unknown even where its term does not mention them, and afterward no array's contents are known.

Calls (`calls.rs`) inline known functions with JavaScript's arity, and run statement lists to their first `return`, so a branch that does not return continues with the statements after it. `throw` evaluates its argument and throws. `try { ... } catch { ... }` is an Either: the block's value where it does not throw, and the handler's (followed by the statements after the `try`) where it does. A read's absent world that throws becomes the handler's value with the `default` family, and a term that throws under a known condition becomes a choice on that condition, with the handler's effects guarded by it. A term that may throw for a reason lowering cannot name is unsupported, as are a block that can fall through, which would let a later throw reach the handler, and `finally`. The handler's parameter binds an unknown value, `undefined` included. Array patterns destructure by iteration, so a string yields its code points. Methods dispatch on what lowering knows about the receiver, after the checks JavaScript makes first: a callback that is not a function throws, and `flat` is modeled at depth one, or zero, which copies.

- A literal list unrolls `map`, `filter`, `find`, `every`, `some`, `reduce`, `join`, `flat`, `flatMap`, `slice` with known bounds, `at`, and `concat`. `filter` appends each element where its keep holds, as a conditional where the keep is symbolic. A separator that may be missing writes the default comma there.
- A short list yields a split whose absent side is the method's unit: `true` for `every`, `false` for `some`, `''` for `join`, `[]` for `flat` and `flatMap`, the initial value for `reduce` (a throw without one), and `0` for a filtered count.
- A symbolic list yields a term. `map`, `filter`, `every`, `some`, and `reduce` (as `fold`) carry their callback, lowered once with fresh element and index binders. `join` and `flat` take the list alone. A fold seed that may be missing flows into the accumulator, where the callback may or may not swallow it, so that flow is undecided.

Before falling back to a term, lowering recognizes a filter or find whose predicate is `index === j` with `j` an integer, and a `reduce` whose callback ignores its accumulator. A callback that ignores its accumulator yields its value on the last element. Without an initial value, a one-element list returns that element without calling the callback, so the law then also requires the callback to return its element. Reading a mapped list applies its callback to the underlying read, with that read's element, index, and list, as `map` would. A short list's callbacks likewise run in the world where its slot is present.

Declarations (`declare.rs`) come first. A source that starts with `declare` is parsed as a program of `declare const` statements and one expression; each statement's type becomes a shape, or for an array or tuple type, an element shape. A declared list is a list whatever its uses; a declared value keeps the kind its uses give it where the two agree (an integer index declared `number`), and is otherwise an `any` variable of its shape, so `declare const s: string; s.length` is a string's length rather than a list's.

`oxc_semantic` provides symbol identity for inlining and for recognizing a projection's index parameter. `usage.rs` uses its node tree to give each free variable its precondition, looking through parentheses and type assertions. A walker's index binder records the list it ranges over. Inside the callback of a walker over `L`, a read of a list `M` is proven in range in two cases, provided `L` is provably no longer than `M`:

- at `L`'s own index;
- at `M`'s first or last element, since the callback runs only on a non-empty list (as does a mapped read's callback, or a short list's, where its read is present).

`L` is provably no longer than `M` when `M` is `L` itself, or is reached from `L` through `map`, `filter`, `slice`, `append`, or a full copy. A read at any other coordinate derived from a walker's index is marked as drift. When such a read reaches a map's result with its absent side still `undefined`, it is emitted as `escape`.

### References and mutation

An array that can be held has an identity. A free list is an input reference. A fresh array becomes a local reference once it is bound to a name, put in another array, stored by a mutation, or made the receiver of a list method, whose callbacks can reach it. An element lowering recomputes, a mapped list's at an index, has a place reference: one key in every world. A conditional between values that hold references is a choice reference, which owns its alternatives. The store (`refs.rs`) holds each reference's current contents, so aliases share them, and `===` decides identity: a reference equals itself, a local or place differs from everything else, and a choice or two inputs stay unknown. An array with no identity was just built, so nothing else can see it change.

The global conversions (`builtins.rs`) are values: `Number`, `String`, `Boolean`, `parseInt`, `parseFloat`, and `JSON.stringify` can be called or passed as callbacks, so `xs.map(Number)` and `xs.filter(Boolean)` lower like any walker. Known arguments fold as JavaScript computes them: `ToNumber` trims JavaScript's white space, reads `0x`, `0o`, and `0b` integers and decimal literals, and folds only safe integers (a fraction or an infinity is a `dyn` number). `parseInt` reads its radix as a 32-bit integer, and `JSON.stringify` quotes and escapes as JSON does, writes an element's `undefined` or function as `null`, and throws on an array that contains itself. Unary `+` is `Number`, and `-` and `*` read a known string or list as the number it spells. An array is written as text with its identity, and one that holds itself writes as empty text where it recurs, as engines join a cyclic array: `[1, a]` with `a` itself writes `1,`. A conversion of a list converts its text, so a read inside the list is lifted before any `dyn` sees it: an operation that is not element by element never receives a possibly missing read. A sort of a literal list runs in each world of its elements' reads for the same reason, and a relational comparison compares a list as its text. The model identifies `-0` with `0`, since nothing it models tells them apart.

`includes` compares by `SameValueZero`, which is strict equality wherever either side cannot be `NaN`; over a symbolic list it is a `some` walker. `reduceRight` folds a literal list from its end and a short list as `reduce` does; over a symbolic list it is not modeled.

A walker over a symbolic list whose callback has no effects and cannot throw is lowered once on symbolic arguments first. If the structure of its truth (`and`, `or`, `not`, and `if`, and the truthiness of a conditional, around the index's equality `0 <= i - k` and `0 <= k - i`) shows that it can hold at only one index `k`, or for `every` fail at only one, the walk depends on the element at `k` alone: it becomes the same walker over the slot `list.slice(k, k + 1)`, the callback still receiving `k`. So `i === k && p`, `i === k ? p : false`, and an early `return false` all decide as the slice does, without matching any spelling. A short list that a filter may empty is written, wherever it becomes a term, as its slot: empty where the read is missing, and the element or nothing where it is present.

`reduce` over a symbolic list types its accumulator when the callback has no effects. The type starts as the seed's, or without one the first element's, and grows with the callback's result until it settles; a callback probed on an accumulator with identity shows whether it mutates or keeps it, and a number stays untyped. So `[...acc, x]` spreads a list rather than an unknown. `forEach` runs its callback for its effects and is undefined. Over a literal list it runs on each element in order, and over a list of at most one element in the present world. Over a symbolic list, when the callback's only effect updates one array the expression holds, that array's contents become a fold over the list, with the callback's update as the body, so `forEach` pushing onto a local array is the same fold as the `reduce` that builds it. Any other effect is unknown afterward. A callback that runs repeatedly and writes, to an array that outlives it, a value depending on a read that may be missing makes the expression opaque, since the unknown array would hide the witness. A read at another collection's coordinate, put into a list's cell while still undefined where missing, is a hole there however the list was built, as in a map.

Mutating methods, assignments to elements and properties, `++`, `--`, and `delete` (`mutate.rs`) update the store functionally. A literal list updates exactly: JavaScript's default sort order for known values, and `splice`, `fill`, and `length` with known arguments; an invalid length throws. A symbolic list becomes a `sort` or `reverse` term, a slice for `pop` and `shift`, an append for `push` and `unshift`, or an uninterpreted list. Contents that are a split update in each world, and mutating through a choice updates each alternative where its test picks it. A literal walker reads its receiver as it is at each step, so a callback that changes its array changes the rest of the walk. Reading a mapped element reruns the callback as the map ran it: with the element, its index, and the receiver, against the store when the map ran. Arrays it builds become plain values, and if the callback wrote to arrays that outlive it, the element is unknown.

A term holds a snapshot of every array whose contents it contains, so lowering keeps such snapshots from going stale. A mutation that would store an array into a symbolic list's term instead makes that list's contents unknown, and writing to an array some term already holds makes every array's contents unknown. Mutating an object whose holder is unknown does the same, since it may be one of the store's arrays. Resolving references into a term memoizes each array per emission, and an array that contains itself has no finite term, so it is unknown.

A mutation is logged with its target's owner: `external` for an input, a value of unknown type from the caller, an element of the caller's list, or a local that escaped into one of the caller's; `internal` for an array the expression holds alone, which is not logged; `unowned` otherwise; and an `if` over the alternatives' owners for a choice. An escape records the owner of what the array escaped into, as a term that joins like the log, so an escape in code that cannot run is no escape.

The store, the escapes, and the log follow lowering's worlds. Each fork lowers both alternatives from the same state and joins what they wrote by the split or the symbolic test that separates them. Under a test, contents that hold references join as a choice between copies of each side's, so no reference is resolved against the wrong store. A value that may throw, by a split or by a conditional that picks a throw at any depth, guards the effects of what follows to the worlds where it does not throw, and masks the result there. An operation that consumes a conditional throw without carrying it, such as truthiness, leaves the expression opaque. A callback lowered once for every element leaves what it wrote unknown, and guards what it logged and let escape by its list holding enough elements: one, or two for a comparator or a `reduce` without a seed. A short list's callback runs only where its slot is present and kept. Literal `every`, `some`, and `find` stop at the first deciding element.

A split leaves lowering as `maybe(family, z, x. f, read, has)`, or as the read itself when it is still `undefined` where missing and the element where present. `has(xs, k)` is the read's own presence test: the read's class also holds its value, and a present element that is `undefined` shares that class with every missing read.

## Core IR: src/core.rs

A typed `egg::define_language!` enum:

- constants, including `throw` and the tagged `unsupported`;
- canonical affine sums (`lin`), products of atoms (`mul`), integer order (`le`, `lt`), and booleans;
- strict equality (`eq`), strings (`concat`, and `text`);
- lists (`nil`, `cons`, `append`, `slice`, `len`);
- walkers over symbolic lists (`map`, `filter`, `every`, `some`, `fold` with bound callbacks; `join` and `flat`);
- reads that may be missing (`read`), reads proven in range (`at`), and presence tests (`has`);
- witnesses (`maybe`), their untagged values (`elim`), and drift escapes (`escape`), each with its read's `has`;
- `dyn`, `dyn?`, and `call`;
- the values of in-place updates (`sort` with a comparator or `undefined`, and `reverse`), and the effect log's `mutate(op, owner)` with owners `external`, `internal`, and `unowned`.

egg never substitutes into a lambda.

## egg: src/engine

The analysis (`analysis.rs`) tracks known constants, integer bounds, the JavaScript types a value can have (its shape), and for a list the shape of its elements. A shape comes from the operation (comparisons are booleans, `concat` is a string, `len` is a number), from a dynamic value's declared shape, or from a variable: an input list's elements are defined, and so is the element a witness binds. Two representations of one value intersect their shapes. Lengths and walker indices are non-negative. A slice whose bounds differ by `d >= 0` holds at most `d` elements, and a conditional lies between its branches. A class proven to hold two constants, or an empty interval, marks the graph inconsistent. A read's presence is the constant value of its `has`, never the value it reads. The rules (`rules.rs`) are:

- boolean and conditional identities, and the normal forms `a < b` as `0 <= b - a - 1` and `a <= b` as `0 <= b - a`, with sums kept in canonical order;
- `read(xs, k)` expands to `if(has(xs, k), at(xs, k), undefined)`, `has(xs, k)` to `0 <= k and k < len(xs)`, and `at(cons(h, t), 0)` is `h`;
- list identities: lengths of `nil`, `cons`, `append`, `map`, a conditional, `sort`, and `reverse`; appends of `nil` and `cons`; walkers, sorts, and reverses of `nil`; a filter whose predicate is `false`; `reverse(reverse(xs)) = xs`; and a default sort of a default sort is the first;
- `[...a, z][0]` is `maybe(default, z, id, a[0])`, and `[z, ...xs][xs.length]` is `maybe(default, z, id, xs[len - 1])`;
- presence context: in a witness whose `z`, or the body of whose `f`, is a conditional on its own `has`, that conditional is its else branch in `z` and its then branch in `f`; when the witness was propagating and the else branch is not `undefined`, the program wrote that branch as a default;
- a witness whose `has` is `false` is its `z`; one whose `has` is `true` is its present branch where that is a constant, and its read where that is the element;
- every `maybe` implies the untagged `elim` of the same value, so spellings that reach one value through different flows share a class.

Detection (`detect.rs`) walks the classes the root's value depends on. It skips a class with a known constant, a decided conditional's dead arm, a witness's side its decided `has` rules out, and a walker's callback over an empty list. A witness or escape counts only if the root has no representative that avoids its class. Detection judges each class's witnesses together, one group per read. Witnesses in one class over one read denote one value: their replacements agree where the read is missing, and their present branches agree on every element. A proof from one representative therefore holds for the whole group: that the branch does not mention the element, that it is free of unknowns, or that the replacement is certainly a value with no throw in it. A branch that avoids the element only by reading the same free list another way may be reading that element, so it is undecided rather than an observation. A witness whose binder is an `item` stays undecided too, since its branch may vary only at the `undefined` element. Before any of this, a group whose replacement is apart from a present branch is honest: the missing read stays visible in the result. Two lists are apart when their lengths, written as sums of cells and unknown lengths at least zero, differ in a fixed direction, as an accumulator does from itself with an element appended. Apartness compares the two classes' facts, splits at conditionals, and splits both together only at a test sharing no variable with the read, as the README's image test describes. A `propagate` witness, which passes the missing read on as `undefined`, is honest only when apart; otherwise its present branch may yield `undefined` too, and it is undecided. The README's verdict section states the conditions.

The effect log is the second root. `mutations` walks it as detection walks a value, skipping decided conditionals, a witness's decided side, and walkers over `nil`. It also carries the conditions of the branches and presence tests it has entered, so a presence test the enclosing branch decides prunes too. It reports each live `mutate` whose owner reaches `external`, and whether any reaches `unowned`.
